# 不完整快照（不要当模型证据）

这里保存两次“没成功”的多层模型快照，用来解释为什么报告只写三层/六层。

---

## 1. `_m2b_8layer_partial.json`

- 现象：`runs.std.frames=153`、`layers=[2]`、`valid=1`；网格为空。
- 原因：扫描/抓取时环形缓冲已被上一轮占满，`/state` 只拿到 153 帧，且大部分落在抬升过程，层量化后只剩 1 个有效格。
- 结论：**不能当 8 层模型**。8 层的页面显示没有留下完整 JSON 快照。

## 2. `_m2b_10layer_truncated.json`

- 现象：JSON 在第 4,195 字节处截断，`json.load` 抛 `Expecting ',' delimiter`。
- 原因：页面每 700 ms 轮询 `/state`，`curl` 抓取被并发请求打断；扫描日志 `_m2b_scan10.log` 显示 10 圈 + 9 次下降都完成了，但 JSON 没抓全。
- 结论：**不能当 10 层模型**。只保留“页面实显 10 层”的定性记录。

## 3. 为什么保留

- 说明“多层上限”不是没做，而是环形缓冲/抓取方式限制了证据；
- 提醒下一个队伍：要留 JSON 快照，先停页面轮询，或让固件把 `/state` 写到文件；
- 报告里据此写“约 8 层”，不写“10 层已验收”。
