## 0. 先记住三句话

1. **这套装置用 1 MHz 超声“摸”物体表面，FPGA 在板上把回波算成“距离”，再把很多个距离拼成三维模型。**
2. **它比“把原始波形传回电脑算”快得多：一帧 342 KB 变成 5 个字节，回读从半秒降到 2.6 毫秒。**
3. **手背上的姿态传感器让模型跟着手转；姿态只改变“看的角度”，不改变“量的结果”。**

如果视频里只能记住三句话，就记这三句。

## 1. 为什么要做这个项目

### 1.1 二维超声的局限

医院里的二维超声，看到的是一张“切面图”。医生要在脑子里把很多张切面拼成三维结构。三维超声能直接给出空间形态，在术前评估、术中观察、穿刺引导里更有用。

但三维不是“多拍几张”：

- **要扫很多角度**：一个回转体要绕一圈、再一层层升降；
- **数据量很大**：一帧原始波形 342 KB，密集成百上千帧；
- **计算很重**：滤波、解调、包络、找峰、标定、重建、比对，一层层叠加；
- **时间必须准**：如果发射由电脑触发，几毫秒抖动就是 1.48 毫米/微秒 × 几毫秒 = 几米的假距离。

### 1.2 一个容易被忽略的问题：模型不能转，就说不清差异

如果三维模型只能用鼠标转，医生在手术台边、双手被占用时很难从特定角度看；更关键的是：

> **如果不能让物体/模型转到差异所在的角度，就只能说“有差异”，说不清“差在哪个方位、哪个高度”。**

所以我们要解决的不只是“重建出来”，而是“重建出来以后，能用手转着看，直接定位差异”。

## 2. 系统长什么样

### 2.1 实物

- 一个透明水槽，里面是水（声耦合介质）；
- 两枚 1 MHz 水浸探头，成 V 形，一发一收；
- 探头装在滑台上，滑台由丝杠带动上下；
- 水槽下方是旋转轴，带着目标转；
- 旁边是 Zynq-7020 主板、双路 ADC、AD8331 接收前端、TC4420 发射驱动、两片 ULN2003 电机驱动；
- 操作者手背上固定一个 MPU6050（加速度+陀螺），用排线接到板子。

对应照片：`report/assets/photo_rig_front.jpg`（正面）、`photo_rig_top.jpg`（俯视）、`photo_electronics.jpg`（电子系统）、`diagram_wiring.png`（接线示意）。

### 2.2 两个运动轴

- **旋转**：28BYJ-48 步进电机，4096 个半步 = 1 圈；24 个方位就是每 15° 一个点；
- **升降**：另一台 28BYJ-48 带 T8 丝杠，4096 个半步 = 2 mm；一层一层往下扫。

扫描时探头只随滑台升降，**不改变俯仰**；目标只旋转、只升降。这样每个点的几何假设才成立。

## 3. 一次测量到底发生了什么

这是整个项目最核心的一段，视频里必须讲清楚。

### 3.1 发一个“滴”，然后安静地听

1. FPGA 产生 **1 MHz、8 个周期**的脉冲，经 TC4420 驱动发射探头；
2. 脉冲进入水里，打到目标表面，反射回来；
3. 接收探头收到回波，经 AD8331 放大，送到双路 10 位 ADC；
4. ADC 以 **5 MSPS**（每秒 500 万个点）采样，两路相减得到 `diff`（11 位有符号）。

### 3.2 一帧有多长

- FPGA 主时钟 50 MHz；
- 一帧 **8192 个时钟 = 163.84 微秒**；
- ADC 每 10 个时钟更新一次 → 5 MSPS；
- 所以一帧有 **819 个有效采样点**。

一帧 = 一次发射 + 一次接收窗口。帧与帧之间隔 11 毫秒，所以一秒约 **90.9 帧**。

### 3.3 FPGA 在板上算什么

```
diff
 → 去直流（DC 阻断）
 → 1 MHz 正交解调（I/Q）
 → 10 点滑动求和（2 微秒，两个载波周期）
 → |I| + |Q| 包络
 → 在样本 280–539（56–107.8 微秒）里找峰值
 → 40 位结果字：valid + frame + idx + amp
```

- **I/Q 解调**：把 1 MHz 的回波拆成两路低频信号，算包络更方便；
- **|I|+|Q|**：不用开方，省 DSP；代价是幅度对相位敏感，所以每帧复位 NCO 相位；
- **窗内找峰**：只关心 56–107.8 微秒这段，窗外不算；
- **40 位字**：每帧只回传 5 个字节，不再传 342 KB 的原始波形。

### 3.4 从“时间”变成“距离”

声速约 1480 m/s = **1.48 毫米/微秒**。

```
声程 L = c × (t − t_eff)
```

`t_eff` 是发射脉冲宽度、电路延迟、渡越时间的等效偏置，用平板标定拟合。

对**竖直圆柱**，反射点就在探头高度，半径：

```
r = R0 − sqrt((L/2)² − a²)
```

`a` 是两探头半间距，`R0` 是扫描轴到探头中点的距离。

对**锥台**，表面法线是斜的，反射点比探头低；如果仍按“同高度”反演，半径会偏大（陡锥可偏 +1.8 mm）。这是几何决定的，不是程序 bug。

## 4. 为什么一定要用 FPGA

如果只是“ADC 采集 → 电脑算”，FPGA 就只是个数据搬运工。我们的 FPGA 真正做了三件事：

### 4.1 确定性：发射和采样同源

- 发射起点到第一个样本由计数器决定，抖动 **20 纳秒**；
- 电脑触发是毫秒级抖动，1 毫秒 = 1.48 米的假距离；
- 电机、采集、位姿都在同一个 50 MHz 时钟域里。

### 4.2 板上出结果：342 KB → 5 B

| | 老办法：ILA 上传 | 现在：板上 DSP |
|---|---:|---:|
| 每帧数据 | 342,172 B | 5 B |
| 单帧回读 | 477–555 ms | 2.48–2.80 ms |
| 加速 | 1 | **171–202×** |

这不是“看起来快”：同一帧、同一算法，板端 40 位字和 Python 定点参考**逐位相同**，四轮独立采集都是零差异。

### 4.3 位姿锁存：给每一帧盖硬件时间戳

步进电机是开环的，电脑只知道“命令它走多少步”，不知道实际走到哪。

我们在 `capture_start` 上升沿，把两轴步数直接锁进寄存器，随这一帧一起读回：

- 读到的是“发射那一刻的步数”；
- 不是“电脑以为它走完的步数”；
- 丢步、命令被吞、先动后采，都能当场发现。

## 5. 数据怎么从 FPGA 到网页

```
PL：采集 + DSP + 位姿锁存
  → AXI 176 位帧记录：seq + pose_rot + pose_lift + 峰值字 + 质心字
  → PS：SEQ 双读防撕裂 → ACK → 8192 帧环形缓冲
  → PS：C 算法（半径/分层/残差）→ /state JSON
  → 浏览器：Canvas 画三维模型
```

几个关键设计：

- **SEQ 双读**：读一次序号、读数据、再读序号；两次不一样就丢弃，不 ACK；
- **ACK 只在读完整后写**：不会 ACK 一条半新半旧的记录；
- **toggle 跨时钟域**：PL 和 AXI 是相关但不同的时钟，用翻转信号 + 两级同步；
- **8192 帧环形缓冲**：约 90 秒 @ 90 fps，满了覆盖最旧；
- **PS 裸机 + lwIP**：板子上跑一个很小的 HTTP 服务，电脑/手机浏览器直接打开。

C 算法和 Python 参考在 4 个真实 run 上 `points.csv` **逐字节相等**，不是“差不多”。

## 6. 三维模型怎么拼出来

### 6.1 扫描计划

- 24 个方位 × 若干层；
- 每层 4096 个半步转一圈；每层之间升降 4096 个半步 = 2 mm；
- 每个格子得到一个飞行时间 → 一个半径。

**一个坑**：24 个方位需要 23 次移动，每次 171 个半步，23×171=3933，而一圈是 4096；每层会少 163 个半步 = 14.34°。下一层又从 0 开始，模型会变成螺旋。所以每层第一个点要补 `rot 163`，让 3933+163=4096。

### 6.2 质量门

不是每个回波都可信。我们要求：

- 信噪比 ≥ 15 dB；
- 次峰比 ≤ 0.6（防止多径选错峰）；
- 不是窗口边缘的峰；
- 至少 2/3 帧合格；
- 重复性 MAD ≤ 0.6 微秒。

不过门的点不定位、不补点，保留拒收原因。

### 6.3 点云 → 剖面 → 网格

- 每个点写成 `(z, az, r)`；
- 层内取中位半径，组成母线 `profile.csv`；
- 在轴对称假设下旋转成开放侧壁 `mesh.ply`；
- **没测到的端面不封盖**——宁可交付一个有洞但诚实的模型，也不要用插值补出“看起来完整”。

### 6.4 真实结果

| 模型 | 格子/有效 | 网格 | z 范围 |
|---|---:|---|---:|
| 三层 | 72 / 71 | 144 顶点 / 192 面 | −2…+2 mm |
| 六层 | 141 / 131 | 288 顶点 / 480 面 | −8…+2 mm |

半径约 14 mm（名义 Ø28 圆柱）；3 圈/层重复性 σ=0.4505 mm（69 个共同格）。

注意：这个半径锚定名义值，**不是绝对尺寸标定**；能比较差异，不能报“绝对精度”。

## 7. 异常检测怎么做

1. 先扫一个“标准件”，把每个 `(z, az)` 的半径存成参考；
2. 再扫“待测件”（比如贴了橡皮泥凸起）；
3. 同一格子相减：`Δr = r_测 − r_参考`；
4. 阈值 `max(3σ, 1.5 mm)`；
5. 超阈格子做连通域聚类，输出缺陷中心、峰值高度、面积、`DETECTED/NO_DETECTION`。

为什么有 1.5 mm 下限？因为机械重复性、开环步进、窄带多径，真实噪声底大约 0.45 mm；阈值不能设得比噪声还低。

**这里必须分清**：

- 数字体模上：8 个凸起全部命中、0 个误报，MAE 0.189 mm；
- 真实凸起的量化结果：见演示视频；
- 不要把“仿真 8/8”说成“真实检出 8 个缺陷”。

## 8. 手背姿态交互是什么

### 8.1 硬件与数据流

```
手背 MPU6050 → I2C 400 kHz → PL
  → 定点互补滤波（CORDIC atan2 + 整数 sqrt，α=31/32）
  → 128 位姿态字：magic + seq + flags + tick + roll/pitch/yaw + err_cnt
  → 独立 AXI 窗口 0x30..0x3C
  → PS 读一致快照 → /api/pose（约 180 B）
  → 浏览器：四元数旋转模型
```

### 8.2 关键设计：姿态只显示，不测量

- 模型几何只由电机步数和超声回波决定；
- 姿态只用于“转模型”；
- 这样手转只改变观察角度，不会让标准件/待测件的测量口径漂移。

### 8.3 实测

- 716.6 Hz 采样（不是 1 kHz）；
- 融合延迟 51 拍；
- 网页 20 Hz 刷新；
- 手转模块，模型同步旋转，同时帧率不受影响。

### 8.4 为什么这是创新点

不是“又一个鼠标替代品”，而是：

> **一边建模、一边用手背把模型转到差异所在的角度，直接看出标准件和待测件差在哪。**

对手术场景，医生不用离开操作位置去碰鼠标；对调试，操作者可以两只手都在设备上。

## 9. 五个创新点（口语版）

1. **把“上传原始波形”改成“板上出结果”**：一车原料在产地加工成一颗螺丝，再运回；不是把整车原料拉回工厂。
2. **发射和位姿同一瞬间锁进同一帧**：给每一帧盖硬件时间戳，不是电脑事后猜。
3. **手背姿态 + 实时建模**：建模过程中手一转，模型跟着转，差异位置直接到眼前。
4. **姿态只改变“看的角度”，不改变“量的结果”**：参考件和待测件始终同一把尺子。
5. **把踩过的坑变成技能包，并给每个数字标来源**：换人、换题也能复用。

## 12. 拍视频前必须想清楚的“边界”

1. **四件全高度、真实凸起**：报告里写“见演示视频”，视频里就一定要有对应画面；拍不到就改回保守说法。
2. **绝对尺寸**：半径锚定名义 Ø28，没有做真实平板标定；视频里说“相对半径约 14 毫米”，不要说“绝对精度 0.02 毫米”。
3. **716.6 Hz**：不是 1 kHz；页面 20 Hz，不是 1 kHz 到网页。
4. **整机加速**：171–202× 是单帧回读；整机扫描受电机限制约 3.3 s→2.3 s，不要说“整机 190×”。
5. **20:14 位流**：716.6 Hz 是在 18:51 同源构建上测的；随包 20:14 版只改排程，未复测。

## 13. 评委可能问的问题（口语答法）

**Q：为什么不用电脑算？**
A：电脑算得动，但数据要先传回去。342 KB/帧、477–555 ms/帧，密集成百上千帧就等不起；而且电脑触发有毫秒级抖动，1 毫秒就是 1.48 米的假距离。FPGA 把这两件事一起解决：板上算完只传 5 字节，发射和采样同源。

**Q：三维模型是真的吗？**
A：三层/六层是板上真实扫出来的，144/192、288/480 个顶点/面；四件 4096 点是数字体模，用来验证算法和显示链路；完整四件流程见演示视频。

**Q：精度多少？**
A：真实重复性 3 圈/层 σ=0.45 mm；数字体模 MAE 0.189 mm；绝对尺寸还没做平板标定，所以只报相对半径和差异，不报绝对精度。

**Q：手背姿态有什么用？**
A：建模过程中用手背把模型转到差异所在的角度，不用鼠标、不离开操作位置；姿态只显示，不参与测量，保证参考件/待测件可比。

**Q：创新在哪？**
A：不是发明新超声算法，而是把“确定性采集 + 板上出结果 + 位姿锁存 + 手背姿态交互 + 可复现证据链”做成一个闭环；每一环都有可验证的数字。

**Q：为什么锥台顶部测不到？**
A：固定俯仰下，锥面法线倾斜，反射点低于探头；陡锥顶部超出接收角。这是几何限制，要加俯仰或多视角。

**Q：8 层/10 层呢？**
A：8192 帧环形缓冲按层扩容前大约 8 层；10 层页面显示过，但没有留下完整 JSON 快照，报告里不把它当验收。

## 14. 一句话结尾（视频最后）

> 这套系统证明：在 XC7Z020 这样的中等规模器件上，可以把超声三维扫描里最“硬”的一段——确定性采集、位姿锁存、正交解调、包络、找峰——放进 FPGA，让 PS 以 90 帧每秒连续读取，让浏览器实时看到模型，让手背一转就能看到差异。它还不是临床设备，但每个数字都能回到文件。
