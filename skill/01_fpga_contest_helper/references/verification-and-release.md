# 验证、故障定位与交付

## 证据分开

| 证据 | 可以说明 | 不能自动说明 |
| --- | --- | --- |
| 静态检查/语法 | 所检查规则未报错 | 全部功能正确 |
| 自检仿真 | 所列输入/参数下逻辑符合期望 | 电气、CDC 亚稳态可靠性或全工况 |
| 综合 | 当前配置可映射并有资源报告 | 布局布线时序通过 |
| 实现/时序 | 当前约束与分析角下的报告结论 | 约束完整或板上功能达标 |
| 下载 | 指定产物已写入/配置 | 实际运行版本和功能正确 |
| 板级测试 | 指定板卡/输入条件下的实测 | 未测条件及重复成功率 |

时序验收检查 setup 与 hold、时钟定义/关系、未约束端点、外部接口覆盖、DRC 和关键告警，记录 WNS/TNS/WHS/THS 或本工具等效指标；没有该项则说明原因。不能只摘 WNS≥0，不能降告警级别来制造“通过”。失败时先辨别约束缺失/错误、CDC、逻辑深度、扇出、布局或资源拥挤，再做最小改动。

## 板上失败的诊断阶梯

先核对实际下载产物和配置模式→电源/时钟/复位→输入原始值→接口极性与协议→CDC/缓存/时序→算法。仿真与实机不同，先构造能区分假设的观测点，避免一开始同时反转逻辑、换引脚和调参数。

若数轮同类修改没有可重复改善，停止盲调，重新核对事实与实验身份。保存失败案例；成功一次只写成功一次。重复测试的次数、冷启动、边界输入、负载与环境覆盖按实际需求约定。

## 实验与发布身份

同一实验记录完整源码快照或可恢复版本、约束/IP 参数、工具版本、构建命令、输入/种子、日志、下载件及 SHA-256。脏工作区仅有 Git commit 不够；记录实际差异或源码清单。哈希相同证明文件一致，不证明该产物由所列源码生成；需要保存真实构建流程及日志。

发布时串行完成：固定当前源集→可复现构建→审查报告→拷贝实际下载件到版本目录→核对哈希→下载并识别运行版本→全链路必要回归→冻结清单。不要只依据文件修改时间判断新旧。

单模块回退应在当前系统副本恢复对应源码再重建，防止其他模块被旧整体 bitstream 回退。最终包同时保留工程重建源、约束、IP 配置/生成步骤、许可依赖说明、测试证据及恢复方法；没有再分发许可的商业工具/IP 不打包复制。

## 报告、演示和评审

按照本届原文核对所需报告、源码、视频和答辩文件；将指标对应到测试编号与原始数据。区分理论估算、工具报告与板级测量，记录单位、条件和失败试次。演示包含启动、输入、输出、异常恢复和当前版本识别；只有用户要求实际提交时才执行对外提交。

```text

板卡、供电/时钟、输入与本次硬件变化：
只改变了：
现象（阶段、时刻、预期与实际）：
做了几次/各次结果/对应波形或照片：
希望助手做：定位 / 修改并验证 / 解释
```

助手给证据支持的判断、已做检查、真实产物、未验证范围及下一项测试，不要求用户重复查可在本地找到的信息。
